# 2026-04-27 — Phase 3.3 + Phase 4 Implementation

## What Was Done

### Phase 3.3 — gRPC Connection Stability (ATITInfraNode project)

**Problem:** Long-lived gRPC channels could silently drop on network hiccups, Unity server restarts, or load-balancer idle timeouts.

**Changes:**
- `ATITInfraNode/Services/UnityRelayService.cs` — complete rewrite with:
  - `BuildChannel()` now uses `SocketsHttpHandler` with keep-alive pings (30s delay, 10s timeout)
  - `EnsureConnectedAsync()` checks `ConnectivityState` before every RPC; rebuilds channel if `TransientFailure` or `Shutdown`
  - All `catch (Exception)` replaced with `catch (RpcException)` — log only, never throw
- `ATITInfraNode/Proto/game_controller_v2.proto` — added `map<string, float> auxiliary = 4` to `AdminCommandRequest`

### Phase 4 — Library Foundation (new projects)

**Two new projects created:**

#### `IoTGame.Core/` — Library (do not modify)
- `Abstractions/` — 5 interfaces: `IDeviceAuthenticator`, `ISessionResolver`, `IPlayerMapper`, `ISessionStore`, `IAdminAuthenticator`

## Key Design Decisions

### SessionId in MQTT payload (Phase 4)
Events now require a `sessionId` field in the MQTT payload. This allows the server to route to the correct Unity instance and look up per-session slot mappings. Events without `sessionId` are dropped with a warning.

### UnityRelayService as channel pool
Instead of a single channel, the relay now maintains a `ConcurrentDictionary<endpoint, ChannelEntry>`. This supports multiple concurrent game sessions each pointing to different Unity servers.

### Shared secret on every gRPC call
If `IoTGame:SharedSecret` is configured, it is sent as `x-iotgame-secret` metadata on every outgoing RPC. Unity validates it server-side.

## Note: ATITInfraNode project (net10.0)
The existing `ATITInfraNode` project targets `net10.0` but only .NET 8 and 9 SDKs are installed in the terminal environment. Phase 3.3 changes were applied correctly but cannot be verified without .NET 10. Use Visual Studio or install the .NET 10 SDK to build it.
