### Phase 6 — Admin Security Dashboard Backend (`GameServer/`)

**New NuGet packages added:**
- `Microsoft.EntityFrameworkCore.Sqlite` — user database
- `Microsoft.EntityFrameworkCore.Design`
- `BCrypt.Net-Next` — password hashing
- `Microsoft.AspNetCore.Authentication.JwtBearer` — dashboard auth
- `System.IdentityModel.Tokens.Jwt`

**New `GameServer/Data/DashboardDbContext.cs` + `DashboardUser.cs`:**
EF Core SQLite context for the admin user table. `PasswordHash` stores bcrypt hash —
plaintext never touches the database. `dashboard.db` is gitignored.

**New `GameServer/Scripts/seed_admin.py`:**
One-time Python script to create the admin user before the demo. Uses `bcrypt` (Python)
to generate a cost-12 hash and inserts it into `dashboard.db` via SQLite directly.

**New `GameServer/Controllers/AuthController.cs`:**
`POST /api/auth/login` — accepts plaintext password over HTTPS, verifies against bcrypt
hash using `BCrypt.Verify` (constant-time), issues a signed JWT on success. Returns the
same `"Invalid credentials"` error for both wrong username and wrong password to prevent
username enumeration.

**New `GameServer/Hubs/SecurityHub.cs`:**
SignalR hub at `/hubs/security` — requires JWT. Pushes real-time events to the React
dashboard: `OnAlert(IntrusionAlert)` and `OnDeviceStateChanged(DeviceSecurityState)`.
JWT is extracted from the `access_token` query parameter for WebSocket connections
(browsers cannot set Authorization headers on WebSocket upgrades).

**New `GameServer/Controllers/SecurityController.cs`:**
REST endpoints under `/api/security/` — all require `[Authorize]`:
- `GET  /api/security/status` — full snapshot (devices + alerts) for initial dashboard load
- `GET  /api/security/devices` — device state list
- `GET  /api/security/alerts` — recent alert feed
- `POST /api/security/devices/{deviceId}/quarantine` — manually quarantine
- `POST /api/security/devices/{deviceId}/unquarantine` — lift quarantine + push SignalR update
- `POST /api/security/alerts/clear` — clear alert feed

**New `GameServer/Models/DashboardModels.cs`:**
Request/response DTOs: `LoginRequest`.

**Updated `GameServer/Program.cs`:**
Added SignalR, JWT bearer auth, EF Core SQLite, `AddControllers()`, static file serving
from `wwwroot/dashboard/`, and SPA fallback route. Middleware order: `UseAuthentication`
→ `UseAuthorization` → `UseStaticFiles`. Database auto-created on startup via
`EnsureCreated()`.

**Updated `GameServer/appsettings.json`:**
Added `Dashboard:JwtSecret`, `Dashboard:JwtExpiryMinutes`, and
`ConnectionStrings:Dashboard` (`Data Source=dashboard.db`).

**Updated `.gitignore`:**
Added `dashboard.db`, `dashboard.db-shm`, `dashboard.db-wal`.

**Static file serving:**
React SPA served from `wwwroot/dashboard/`. Build output copied manually with
`scripts/deploy-dashboard.sh`. All `/dashboard/*` routes fall back to `index.html`.
CORS enabled for `http://localhost:5173` in Development only (required for SignalR).

### Phase 6 — Mutual TLS Firmware Authentication (ESP32 firmware project)

**New `scripts/gen_ca.sh`:**
Generates project root CA (4096-bit RSA, 10-year validity). CA private key stays on
provisioning machine — never committed or distributed.

**New `scripts/gen_device_cert.sh`:**
Signs a per-device certificate (2048-bit RSA, 2-year validity). CN must match the
`deviceId` used in the device registry. CSR is created and deleted; only `.crt` is kept.

**New `scripts/provision_device.py`:**
Flashes `ca.crt`, `device.crt`, and `device.key` onto an ESP32 via `mpremote`.

**Updated `iotgame/mqtt.py`:**
Full mutual TLS support — loads CA cert, client cert, and private key from the filesystem.
Sets `ssl_params["cert_reqs"] = ussl.CERT_REQUIRED` to validate broker cert. Passes client
cert/key for mutual authentication. Username/password set to `None` when cert auth is used.

**Updated `game/config.py`:**
Replaced `MQTT_USER`/`MQTT_PASSWORD` with `CA_CERT_PATH`, `CERT_PATH`, `KEY_PATH`.
`MQTT_USER` and `MQTT_PASSWORD` set to `None`.

**New `tools/rogue_device.py`:**
Python simulator for three demo attack scenarios (requires `paho-mqtt`):
- `no-cert` — connects without a client certificate → rejected at TLS handshake
- `flood` — sends 200 events/sec using a valid-looking device ID → triggers rate-limit quarantine
- `spoof-slot` — publishes an unknown `slotId` (`inject-admin`) → triggers unknown-slot alert

**Mosquitto broker config (`/etc/mosquitto/mosquitto.conf`):**
`require_certificate true` and `use_identity_as_username true`. Per-device ACL using
`pattern write game/devices/%u/#` so each device can only publish to its own topic prefix.

**New `certs/.gitignore`:**
Ignores `*.key`, `*.p12`, `*.pfx`. `ca.crt` and `*/device.crt` are committed.

## Setup Required Before Running Phase 6

### 1. Install new NuGet packages (GameServer)

```bash
cd GameServer
dotnet add package Microsoft.EntityFrameworkCore.Sqlite
dotnet add package Microsoft.EntityFrameworkCore.Design
dotnet add package BCrypt.Net-Next
dotnet add package Microsoft.AspNetCore.Authentication.JwtBearer
dotnet add package System.IdentityModel.Tokens.Jwt
```

### 2. Set JWT secret in `appsettings.json`

Replace the placeholder with a real secret (minimum 32 characters):

```json
{
  "Dashboard": {
    "JwtSecret": "replace-this-with-a-real-32-char-secret",
    "JwtExpiryMinutes": 60
  },
  "ConnectionStrings": {
    "Dashboard": "Data Source=dashboard.db"
  }
}
```

Keep the JWT secret out of source control in production — use an environment variable:
```bash
Dashboard__JwtSecret=your-secret-here
```

### 3. Create the admin user (once, before first login)

`dashboard.db` is auto-created on server startup. Run the seed script after the first
`dotnet run` to insert the admin user:

```bash
cd GameServer
dotnet run &          # start server so dashboard.db is created
pip install bcrypt    # if not already installed
python Scripts/seed_admin.py your-demo-password
```

Or run the script against an existing `dashboard.db` file directly without starting the server first.

### 4. Generate CA and device certificates (firmware project — one-time)

Run from the firmware project root:

```bash
# 1. Generate root CA (once per project)
bash scripts/gen_ca.sh
# Produces: certs/ca.key (KEEP SECRET), certs/ca.crt

# 2. Generate a cert for each device
bash scripts/gen_device_cert.sh esp32-device-1
bash scripts/gen_device_cert.sh esp32-device-2
# Optional: generate a rogue cert for the demo attack scripts
bash scripts/gen_device_cert.sh rogue
```

### 5. Flash certificates onto each ESP32

```bash
# Connect ESP32 via USB, then:
python scripts/provision_device.py esp32-device-1 --port /dev/ttyUSB0
python scripts/provision_device.py esp32-device-2 --port /dev/ttyUSB0
```

Verify with `mpremote connect <port> ls` — you should see `ca.crt`, `device.crt`, `device.key`.

### 6. Update Mosquitto broker config

Add to `/etc/mosquitto/mosquitto.conf`:

```
require_certificate true
use_identity_as_username true
acl_file /etc/mosquitto/acl.conf
```

Add to `/etc/mosquitto/acl.conf`:

```
pattern write game/devices/%u/#

user aspnet-server
topic read game/devices/#
```

Restart Mosquitto after changes: `sudo systemctl restart mosquitto`

### 7. Deploy the React dashboard (optional — for the built SPA)

```bash
# From the dashboard frontend project
npm run build
cp -r dist/* ../ATITFinalProject-server/GameServer/wwwroot/dashboard/
```

The dashboard is then served at `http://localhost:<port>/dashboard/`.
During development, run the Vite dev server separately (`npm run dev`) — CORS is
already configured for `http://localhost:5173` in Development mode.

## Known Limitations (Documented)

| Limitation | Production solution |
|---|---|
| No MFA on dashboard login | Add TOTP second factor |
| JWT not revocable | Token blacklist in Redis or short expiry + refresh tokens |
| Single admin user | Add user management endpoints with roles |
| No login rate limiting | `AspNetCoreRateLimit` package, 5 attempts/minute |
| ESP32 secure boot not implemented | Requires eFuse burning — irreversible, out of scope |
